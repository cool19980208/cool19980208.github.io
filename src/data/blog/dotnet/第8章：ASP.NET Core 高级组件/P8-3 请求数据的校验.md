无论是进行MVC还是Web API项目开发，我们都应该对请求数据的合法性进行校验
- 比如重置密码操作，检查两次输入密码是否一致等
- 对请求数据进行充分的合法性校验不仅有助于提升用户界面的友好性，而且有助于提高后台程序的安全性和稳定性

对于一般情况下，前端人员也会对其进行校验。
- 但如果有恶意用户绕过客户端直接向服务器发起请求，这个时候服务器端也需要对于客户端开发人员对数据校验不到位的地方做兜底的工作。
- 因此，服务器端校验必不可少

### 3、.NET Core 内置的校验机制的问题

无论是通过在属性上标注校验规则Attribute的方式，还是实现IValidatableObject借口的方式。
我们的**校验规则都是和模型类耦合在一起**，这违反了==面向对象的“单一职责原则”==；
- 违反“单一职责原则”，这个对于大型项目来说，很严重~

.NET Core 内置的校验规则不够多，很多常用的校验都需要我们编写自定义校验规则，而且写起来麻烦。
- 这个可以通过去找第三方开源库去解决

## FluentValidation的基本使用

在上述我们提到了.NET Core 内置的数据校验机制的不足，杨老师推荐了一个很优秀的数据校验框架
- FluentValidation

### FluentValidation

它可以让我们用类似于EF Core中Fluent API的方式进行校验规则的配置，也就是我们可以把对模型类的校验放到单独的校验类中。

支持
- 控制台、WPF、ASP.NET Core 等各种.NET项目中，这里我们只学习在ASP.NET Core项目中的用法

好处
- 使用FluentValidation以后，我们可以把数据校验的规则写到单独的数据校验类中。
- 这样模型类和数据校验类各司其职，符合“单一职责原则”，而且在FluentValidation中编写自定义校验代码也更加简单

FluentValidation和.NET Core 内置
- 两者的检验方式是可以共存的(好似EF Core和SqlSugar一样，可以混用)
- 不过为了代码的统一，建议不要混用这两者

### 基本使用

第一步：先在项目中安装NuGet包
- Install-Package FluentValidation.AspNetCore -Version 10.3.6   
- 杨老师当时演示用的是10.3.6的版本

第二步：在Program.cs中添加注册相关服务的代码

- 需要注意的是，如果是多项目的话，需要指定获取入口的程序集，具体可以看书的270页

    Assembly assembly = Assembly.GetExecutingAssembly();

## FluentValidation中注入服务


在编写数据校验代码的时候，有时候我们需要调用依赖注入容器中的服务

FluentValidation中的数据校验类是通过依赖注入容器实例化的，因此我们同样可以通过构造方法来向数据校验类中注入服务

- Must 是普通校验 ；MustAsync 是异步校验规则
- 可以进一步自定义规则的显示
	- `WithMessage(x => $"密码{x.Password}和{x.Password2}不一致");`

```C#
public AddNewUserRequestValidator(UserManager<User> userManager)//注入User函数
{

	RuleFor(x => x.UserName).NotNull().Length(3, 10)
		.MustAsync(async (x,_) => await userManager.FindByNameAsync(x) == null)//连接数据库，查询这个用户名是否已存在。如果存在就不创建了
		.WithMessage(x=>$"用户名{x.UserName}已经存在")
		//.WithMessage("账号长度必须介于3到10之间")
		;
	RuleFor(x => x.Password).Equal(x => x.Password2).WithMessage("两次密码必须一致")
		.WithMessage(x => $"密码{x.Password}和{x.Password2}不一致");
}
```
